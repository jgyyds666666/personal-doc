## 1. 执行目标

结合以下两份方案，先交付可独立使用的文本编辑基础，再进入知识库建设：

- [纯文本、Markdown、JSON、CSV 与代码文件在线编辑方案](./TEXT_AND_CODE_FILE_EDITOR_PLAN.md)
- [个人知识库功能实施方案](./KNOWLEDGE_BASE_IMPLEMENTATION_PLAN.md)

最终目标：

1. 文件列表展示真实大小和修改时间，并支持分页。
2. TXT、Markdown、JSON、CSV 与常见代码文件可以安全在线编辑。
3. 保存保留 UTF-8 BOM、LF/CRLF 和文件末尾换行。
4. 通过 ETag 检测并发修改，禁止静默覆盖。
5. Markdown 可以安全预览，上传代码永远不执行。
6. 后续增加目录、标签、内容索引、中文/代码搜索。
7. AI 语义检索和问答保持可选，不影响基础知识库。

## 4. 已确认的技术决策

- S3 继续作为原文件事实来源。
- 编辑文件默认上限为 2 MiB。
- 第一版仅支持 UTF-8 和 UTF-8 BOM。
- 编辑器使用 CodeMirror 6。
- Markdown 使用 React 安全渲染，不支持 MDX、脚本、iframe 和原始 HTML 执行。
- CSV 第一版按文本编辑，不做电子表格组件。
- 第一版手动保存，不对每次输入执行 S3 自动保存。
- 代码文件只编辑，不编译、不运行、不调试。
- 不在当前 1 核 2 GB 服务器运行本地大模型。

## 5. 风险与保护措施

| 风险 | 保护措施 |
| --- | --- |
| 两个页面覆盖同一文件 | ETag 乐观锁，冲突返回 409 |
| 二进制文件被当作文本 | 扩展名白名单 + NUL/UTF-8 检测 |
| Markdown XSS | 禁止原始 HTML执行 + 固定插件 + sanitize |
| 代码被执行 | 只使用文本编辑器，不提供运行和 HTML 预览 |
| 大文件拖垮浏览器 | 服务端 2 MiB 上限 |
| 保存破坏换行或 BOM | 检测并按原策略编码 |
| 保存失败造成丢失 | 编辑器保留当前内容，成功后才清除 dirty 状态 |
| 存储提供商不支持条件写 | 保存前核对 ETag；部署侧开启对象版本控制作为恢复保障 |
